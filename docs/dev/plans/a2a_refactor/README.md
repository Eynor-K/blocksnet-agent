## Порядок работы

Шаги пронумерованы. **Идти строго по порядку**, кроме явно отмеченных
параллельных веток. Каждый шаг — отдельный файл со структурой:

- **Цель** — одна фраза, зачем шаг существует
- **Предусловия** — что должно быть готово
- **Задачи** — пронумерованные, с точными путями файлов
- **Тесты** — что написать и что оно должно проверять
- **DoD** — проверяемые критерии готовности (команда + ожидаемый результат)
- **Не делать** — типичные ошибки на этом шаге
- **Откат** — как вернуться, если пошло не так

## Инварианты — нарушать нельзя

Эти правила выведены из сверки с кодом; их нарушение даёт **тихий** регресс
(тесты зелёные, качество ответов падает).

1. **`blocksnet_agent/agent.py` не редактируется.** Ни строки. Если кажется,
   что нужно — шаг спроектирован неверно, остановись и зафиксируй вопрос.
2. **Агент вызывает инструменты in-process.** Никаких MCP-клиентов внутри
   агента. Причина: `state`, который пишут tools, читают `overlay_candidates`,
   верификация гипотез, `confidence_basis`, `valid_block_ids`. Граница
   процесса рвёт это без единого исключения в логах.
3. **`blocksnet_agent/tools/registry.py` не трогать** — это существующий
   RAG-слой (`find_tools`, `get_tool_help`, синонимы сервисов), а не реестр
   спецификаций. Новый каталог называется `catalog.py`.
4. **Текстовый выход инструментов не менять.** Строки парсят `metrics.py`
   и `hypotheses.py`. Оборачивать — можно, переформатировать — нет.
5. **`submit_answer` не экспонировать в MCP.** Терминальный инструмент
   агентского цикла, пишет `state["_submitted_answer"]`.
6. **Существующие тесты остаются зелёными без правок.** Единственное
   допустимое изменение — добавление новых. Если старый тест краснеет —
   это регресс, а не устаревший тест.
7. **Никаких захардкоженных чисел инструментов** в коде и тестах.
   Число меняется; сверка идёт с фактическим набором `make_tools()`.

## Соглашения

- **Коммиты**: один шаг — один коммит, префикс `a2a/NN: <что>`,
  например `a2a/03: MCP exposes 32 raw tools via catalog`.
- **Ветка**: `feat/a2a-refactor`, от `main`.
- **Язык**: docstring и комментарии — русский (как в существующем коде),
  имена — английские.
- **Стиль**: `from __future__ import annotations` в новых модулях,
  type hints обязательны, длина строки как в соседних файлах (~120).
- **Тесты**: pytest, без сетевых вызовов и без реального LLM
  (см. существующий `tests/test_async_mcp_contract.py` как образец
  monkeypatch-подхода).
- **Не запускать** полные прогоны агента (LLM) в тестах — только моки.

## Если что-то пошло не так

- Шаг оказался невыполним как описан → **не импровизируй молча**: запиши
  расхождение в `docs/a2a_refactor/implementation/deviations.md`
  (создать при первой записи: шаг, что ожидалось, что в коде, что сделал).
- Требуется править `agent.py`, `hypotheses.py` или `metrics.py` →
  остановись, это выход за границы плана.
- Тест из `tests/` покраснел → откатывай последний шаг, а не правь тест.
