# Реализация улучшений BlocksNetAgent (Tier 1 + Tier 2)

Реализовано по [improvement_plan.md](improvement_plan.md). Код изменён в рабочем дереве основного
репозитория (`blocksnet_agent/…`) — там живёт версия со слоем согласованности M1–M3, по которой
запускались эксперименты. Все изменённые модули проходят `py_compile`; ключевые эвристики
(распознавание block_id, генеративности, мемоизация через `model_copy`) проверены точечными тестами.

> ⚠️ Валидация перезапуском ноутбуков требует `.env` (API-ключ FP2MP) и недоступна в этой сессии —
> прогон `experiment_1/2.ipynb` остаётся за вами. Ожидаемые эффекты описаны ниже по пунктам.

## Что сделано

| ID | Файл(ы) | Суть правки |
|---|---|---|
| **T1.1** Entity-grounding | `agent.py`, `prompts.py` | `_mentioned_block_ids()` извлекает «квартал N»/`block N`; `_build_context()` инжектит директиву «вызови get_block_info(N), не выдавай городские агрегаты за квартал»; `_entity_grounding_issue()` в M1 требует, чтобы N реально фигурировал в вызовах → иначе реентри; иначе — лимитация + confidence ≤ 0.55 |
| **T1.2** Дедуп вызовов | `tools/__init__.py`, `agent.py` | `_memoize_tools()` оборачивает идемпотентные `compute_/list_/get_/load_` кэшем `(tool,args)→observation` на запуск (через `model_copy`); реентри-промпт получает список «Уже выполнено», чтобы не повторять вызовы |
| **T1.3** Бюджет артефактов | `provision.py`, `viz.py`, `runtime.py` | Батч (`key/basic/…`) считает `save_artifacts=False` → только сводный CSV, без 34×CSV/links/PNG; `RunLogger.MAP_BUDGET=24` + `reserve_map()` ограничивает число картограмм на запуск |
| **T1.4** Гарантия плана | `agent.py` | `_ensure_plan()` восстанавливает ANALYSIS PLAN из выполненных вызовов, если модель его не выдала; `_merge_sections` защищён комментарием/логикой от затирания плана |
| **T1.5** Единый confidence | `agent.py`, `runtime.py` | Авторитетный — авто-скоринг; самооценка модели сохраняется как `SELF_CONFIDENCE`; в `run_log.md` отдельная секция `## Confidence` (scored + self-reported) и `## Limitations` |
| **T2.1** Hypothesis-first | `prompts.py` | ANALYSIS PLAN обязан содержать 2–5 гипотез, для каждой — инструмент-тест; запрет расчётов, не привязанных к гипотезе |
| **T2.2** Self-critic | `agent.py` | `_consistency_critic()` — один домен-нейтральный LLM-проход на противоречия RESULT↔REFLECTION↔HYPOTHESES (несведённые списки кварталов, неинформативное среднее) → реентри |
| **T2.3** Скошенная статистика | `provision.py` | `_skew_note()` добавляет в наблюдение `compute_shared_provision` пометку «опирайся на медиану/перцентили» при std≫mean / median=0 / mean≫median |
| **T2.4** Цикл развитие→тест | `prompts.py`, `agent.py` | `_is_generative()` + директива в контексте; `_generative_issue()` требует `compute_scenario_provision` (before→after) для генеративных вопросов → иначе реентри/лимитация |
| **T2.5** 3-проходный синтез | — | Отложен (в плане помечен опциональным). |

## Ожидаемый эффект на экспериментах

**Эксп.2 «что нужно разместить в квартале 603?»** (теперь block_ids=[603], generative=True):
- Принудительный `get_block_info(603)`; если квартал не заземлён — реентри, затем лимитация и confidence ≤ 0.55. Городские агрегаты больше не выдаются за показатели 603.
- Требуется `compute_scenario_provision` (измеренный эффект) — иначе явная лимитация.
- Батч `key` сохранит 1 сводный CSV вместо 71 CSV + 35 PNG; дубли вызовов схлопнутся мемоизацией.
- ANALYSIS PLAN гарантирован.

**Эксп.1 «где нужно разместить новые школы?»** (generative=True):
- Self-critic должен поймать несведённые списки «центральные vs нулевой обеспеченности» и потребовать единый приоритет.
- Скошенное среднее `shared_provision` (2180 при медиане 0) получит пометку.
- Требование измеренного сценария развития (suggest_target_blocks → propose_zone_development → scenario).
- Дубли вызовов схлопнутся; единый confidence в логе.

## Замечания и риски

- **Реентри добавляет LLM-вызовы** (entity/critic/generative проверки). Бюджет реентри ограничен `_MAX_REENTRY=2`, но стоимость прогона вырастет. При необходимости — отключить critic для не-широких вопросов.
- **`_entity_grounding_issue` эвристичен**: проверяет присутствие числа block_id в тексте вызовов (`\bN\b`); теоретически возможно ложное «заземление», если N случайно встретится в значениях. Директива на `get_block_info` снижает риск.
- **Мемоизация — на один запуск**: кэш живёт внутри `make_tools()` (вызывается раз за `run()`), между запусками не протекает; артефакты нового запуска не подменяются старыми.
- **T2.5 (3-проходный синтез)** не реализован — при желании добавить отдельной итерацией.
